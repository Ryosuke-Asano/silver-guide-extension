# 比較デモ同封版：当日の使い方

**まず [当日の手順書](../demo/day-of.html) を開いてください。** 配布ZIPの `はじめに.html` と同じ内容で、インターネット接続なしで読めます。準備・比較・保存の3ステップと、印刷できる架空の入力カードをまとめています。

この版は `codex/bundled-comparison-demo` 専用です。デモの実行にサーバー・Node.js・Wi-Fi接続は不要です。

## 1. 準備する

1. 配布ZIPを展開して、**Chromeフォルダー**を端末に保存します。
2. Chromeのアドレス欄に `chrome://extensions` と入力します。
3. 「デベロッパーモード」をオンにして、「パッケージ化されていない拡張機能を読み込む」で `manifest.json` が直接入っている **Chromeフォルダー**を選びます。
4. 「比較デモを始める」が開きます。閉じたら、`chrome://extensions` でSilver Guideの「詳細」→「拡張機能のオプション」から開きます。
5. 「記録せずに練習する」で両方式を試します。「練習（記録しません）」を確認し、PDFへの記入・保存・添付と、模擬完了まで進めることを確かめます。終了後は「練習を終えて開始画面へ」で戻ります。

Chromebookが2台使えれば両方に同じパッケージを入れます。導入が管理者に制限されている、またはPDFを編集できない場合は、持参Macで両方式を実施します。Chromebook本体の開発者モードへ変更する必要はありません。ChromeOS実機と貸出端末の導入制限は、事前には検証できていません。

**「支援なし」でも拡張を無効にしません。** 開始画面の方式選択で入力補助を停止します。これは、同じ拡張内での支援あり／支援なしの比較です。

## 2. 参加者ごとに比較する

1. 開始画面で参加者番号を設定して方式を選びます。同じ人は両方式・両端末で同じ番号、次の人は別の番号にします。
2. 「入力をクリアして計測開始」を押し、「計測中：参加者 …」を確認してから入力します。本番のフォームは計測開始前には入力できません。
3. 手順書の架空の入力カードで、先にフォーム、その後にPDFを入力します。
4. 支援なしは「図書館利用申込書.pdf をダウンロード」→ PDF編集・保存 →「記入済み申込書のアップロード」→「入力内容を確認する」→「この内容で完了（模擬）」。
5. 支援ありは「Silver Guideで記入」→ 14項目の入力 →「入力を完了」。自動添付・模擬完了まで進みます。基本情報に不備があれば、その修正も時間に含めます。
6. 完了画面で「記録しました：1周 … ／ PDF作業 …」を確認します。「同じ参加者でSilver Guideありへ」または「同じ参加者で支援なしへ」から残りの方式を実施します。参加者番号は引き継がれます。
7. 「計測結果・CSV」で、その人に両方式の完了記録とPDF作業時間があることを確認します。両方式を終えたら「次の参加者・開始画面へ」で戻り、次の参加者番号を設定します。

奇数の参加者は「支援なし → あり」、偶数の参加者は「あり → 支援なし」にします。2台でも同じ人が両方式を実施します。可能なら方式と端末の組み合わせも交互にします。MacとChromeOSの記録は、同じ参加者番号でも1組として集計しません。

本番の計測中は記入済みPDFの添付が必要です。操作だけ試す場合は、開始画面の「記録せずに練習する」を使います。

計測中にやり直す場合は、元のフォームの「計測を中止」を押してから新たに開始します。PDFの記入画面だけを閉じても、元のフォームでの計測は続きます。「保存を再試行」が出たら保存を確認するまで閉じません。

### 支援なしのPDF編集

- **Chromebook：**「ファイル」でダウンロードしたPDFを開き、ギャラリーの「テキスト」で文字を配置します。ペンで新規登録の□にチェックを入れ、「保存」します。[Googleの公式手順](https://support.google.com/chromebook/answer/12453461?hl=ja)
- **Mac：** ダウンロードしたPDFを「プレビュー」で開き、マークアップの「テキスト」で文字を配置します。スケッチで新規登録の□にチェックを入れ、「ファイル」→「保存」します。[Appleの公式手順](https://support.apple.com/ja-jp/guide/preview/prvw11580/mac)

保存したPDFを開き直し、文字とチェックが残っていることを確認してから添付します。編集ソフトを途中で変えず、進行者がソフト名をメモします。貸出Chromebookでの日本語入力・保存は、開始前の練習で確認します。

## 3. 返却前に記録を持ち帰る

**各端末で、CSVとJSONを両方保存します。**

1. 「計測結果・CSV」から「CSVを保存」を押します。
2. 「端末間で移す記録を保存」を押して `silver-guide-records.json` を保存します。
3. 使用した全端末で実施し、USB等で持参Macなど持ち帰れる場所へコピーします。端末ごとにフォルダーを分け、同名ファイルを上書きしないようにします。
4. まとめる端末の結果画面で「他の端末の記録を取り込む」から各JSONを選択します。JSONは同じ記録を再度取り込んでも二重に加算しません。CSVは取り込み用ではありません。
5. 両方式の記録が表示されたことを確認し、統合後のCSVとJSONも保存します。

貸出端末のダウンロードフォルダーだけに残して返却しないでください。コピー確認が済むまで、拡張やChromeプロフィールを削除しません。通常のChromeプロフィールを使い、シークレットや毎回消えるゲストプロフィールは避けます。

## 計測の意味と記録の扱い

- **1周：**「計測開始」から「模擬完了」まで。
- **PDF作業：** 原本のダウンロード／「Silver Guideで記入」から、記入済みPDFの添付形式確認まで。
- **読込・準備・出力：** Silver GuideのPDF処理時間。PDF作業時間の内訳です。

結果画面では平均・中央値と、同じ参加者・同じOSの両方式を1対1にした差を表示します。PDFなし・開始不明・未完了の回は比較集計の対象外です。突然終了した回を完了扱いにせず、保存失敗の再試行でも最初の終点の時間を維持します。

記録はChromeプロフィール内のIndexedDBに保存されます。氏名・住所・フォームの値・選択文章・PDF・ファイル名は記録しません。移行用ファイルも参加者番号・方式・時間・日時・OS種別・ビルドIDなどの計測情報だけです。

## 開発者向け

既存の依存パッケージを入れた環境で `npm run build:chromium` を実行すると、`dist-chromium/demo/` を含む拡張を生成します。配布時は `dist-chromium/` 全体を `Chrome/` としてZIPに入れ、`demo/day-of.html` をZIP直下の `はじめに.html` にコピーします。開発用の鍵・回答・計測ファイルは配布しません。

通常の `npm run dev:demo` と拡張を読み込まない `--manual` も引き続き使えます。HTTP(S)上の汎用PDF連携と同封デモの連携では、送信元の検証を分けています。ChromeOS実機は未検証です。手作業側の自動試験は添付経路を確認するもので、人の入力時間やOS標準PDF編集ソフトの操作は代用しません。
