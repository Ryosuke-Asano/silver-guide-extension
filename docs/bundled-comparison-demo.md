# 同封デモ：当日の使い方

**まず [当日の手順書](../demo/day-of.html) を開いてください。** 配布ZIPの `はじめに.html` と同じ内容です。準備・フォーム入力・PDF記入と模擬完了の3ステップと、印刷できる架空の入力カードをまとめています。

この版は `codex/bundled-comparison-demo` 専用です。デモの実行にサーバー・Node.js・Wi-Fi接続は不要です。

## 1. 準備する

1. 配布ZIPを展開して、**Chromeフォルダー**を端末に保存します。
2. Chromeのアドレス欄に `chrome://extensions` と入力します。
3. 「デベロッパーモード」をオンにして、「パッケージ化されていない拡張機能を読み込む」で `manifest.json` が直接入っている **Chromeフォルダー**を選びます。
4. 「比較デモを始める」が開きます。閉じたら、`chrome://extensions` でSilver Guideの「詳細」→「拡張機能のオプション」から開きます。
5. 「支援なし」または「Silver Guideあり」を選ぶと、そのままフォームを入力できます。

Chromebookが2台使えれば両方に同じパッケージを入れます。導入が管理者に制限されている、またはPDFを編集できない場合は、持参Macで両方式を試します。Chromebook本体の開発者モードへ変更する必要はありません。ChromeOS実機と貸出端末の導入制限は、事前には検証できていません。

**「支援なし」でも拡張を無効にしません。** 開始画面の方式選択で入力補助を停止します。

## 2. フォームを入力する

下の架空の入力カードで、名前・生年月日・住所・電話番号を入力します。ページを開いてすぐ入力できます。登録条件は「在住」、予約受取館は「中央図書館」、予約連絡方法は「連絡不要」にし、E-mailは空欄です。

入力後、E-mail欄の下の申込書（PDF）へ進みます。PDFを使わず、フォームの入力・確認・修正だけを試すこともできます。

## 3. PDFを記入して模擬完了へ進む

- **Silver Guideあり：**「Silver Guideで記入」→ 14項目の入力 →「入力を完了」。自動でPDFを添付し、模擬完了まで進みます。基本情報に不備があれば、元のフォームで修正して続けます。
- **支援なし：**「図書館利用申込書.pdf をダウンロード」→ PDF編集・保存 →「記入済み申込書のアップロード」→「入力内容を確認する」→「この内容で完了（模擬）」。

元のフォームに「入力の検証が完了しました」と表示されれば完了です。実際の申請やファイル送信は行いません。やり直す場合は「最初から試す」、方式を変える場合はページ最下部の「デモの開始画面へ」を使います。

### 支援なしのPDF編集

- **Chromebook：**「ファイル」でダウンロードしたPDFを開き、ギャラリーの「テキスト」で文字を配置します。ペンで新規登録の□にチェックを入れ、「保存」します。[Googleの公式手順](https://support.google.com/chromebook/answer/12453461?hl=ja)
- **Mac：** ダウンロードしたPDFを「プレビュー」で開き、マークアップの「テキスト」で文字を配置します。スケッチで新規登録の□にチェックを入れ、「ファイル」→「保存」します。[Appleの公式手順](https://support.apple.com/ja-jp/guide/preview/prvw11580/mac)

保存したPDFを開き直し、文字とチェックが残っていることを確認してから添付します。貸出Chromebookでの日本語入力・保存は、開始前の練習で確認します。

## データの扱い

フォームの値とPDFは、開いているタブ内で扱います。入力時間の計測、操作の記録、結果の保存・集計は行いません。自分で保存したPDFを残したい場合は、使用した端末から持ち帰ってください。

## 開発者向け

既存の依存パッケージを入れた環境で `npm run build:chromium` を実行すると、`dist-chromium/demo/` を含む拡張を生成します。配布時は `dist-chromium/` 全体を `Chrome/` としてZIPに入れ、`demo/day-of.html` をZIP直下の `はじめに.html` にコピーします。

通常の `npm run dev:demo` と拡張を読み込まない `--manual` も使えます。HTTP(S)上の汎用PDF連携と同封デモの連携では、送信元の検証を分けています。手作業側の自動試験は添付経路を確認するもので、OS標準PDF編集アプリの操作は代用しません。
