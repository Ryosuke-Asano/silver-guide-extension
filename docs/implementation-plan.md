# 実装の進め方

## フェーズ 1 — 共通基盤

- 独立した MV3 拡張機能プロジェクトを作成する。
- ポップアップ、設定、Shadow DOM の支援 UI、ローカル用語辞書を実装する。
- 任意ページで明示開始・停止できる用語ツールチップをテストする。

**完了条件**: 既存ページを壊さず、入力値を扱わず、キーボードだけで用語説明を使える。

## フェーズ 2 — 行政ページのガイドパック

- 最初に対応する行政情報ページと申請ページを、公開 URL ごとに選定する。
- 画面構造の確認、用語のレビュー、公式導線の確認を行い、ガイドパックを作成する。
- 実際の公開ページでドック、項目別ヒント、次項目移動を確認する。

**完了条件**: 選定したページで、公開構造に合った説明と公式導線だけを表示できる。改版時は詳細支援を安全に止められる。

## フェーズ 3 — アクセシビリティと実利用確認

- 文字サイズ、キーボード、読み上げ、低速環境、ページ崩れを確認する。
- 支援文が制度判断や誤った申請誘導にならないよう、担当者レビューを行う。
- プライバシー確認として、ネットワーク・ストレージ・ログにフォーム値が出ないことを検査する。

**完了条件**: 対象サイトごとに再現可能な確認記録を残し、利用者が支援を停止・閉じる操作を常に行える。

## 実装開始に必要な入力

フォーム支援と公式導線はサイト固有の確認が必要なため、次のいずれかを最初のガイドパックの対象として受け取ってから実装する。

1. 公開されている行政案内ページの URL
2. 公開されている申請ページの URL
3. 実サイトを模した検証用 HTML と、画面ごとの正しい案内文・導線

ログイン後の画面や実在する個人情報を入力した画面は不要である。公開情報だけで設計・テストを行う。
