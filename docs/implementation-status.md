## 採用構成

- MV3 WebExtension。ポップアップは入口、専用タブは作業と保管庫、content scriptは元ページの本文・欄と明示反映、backgroundは対象タブの検証と関連管理を担当。元PDFや復号鍵をbackgroundへ送らない。
- Chromiumは専用タブをprivateでも開けるよう`incognito: split`を指定し、アプリ側では通常の保管庫・案内履歴へのアクセスを停止する。Geckoには未対応のsplit指定を入れない。[Chromeのprivate拡張ページ仕様](https://developer.chrome.com/docs/extensions/reference/manifest/incognito)
- React 19、TypeScript、Vite。content scriptは注入可能な単一IIFE、backgroundはモジュール。Floorp/FirefoxとChromiumのmanifestを別ビルドする。
- PDF.js 6.4.299、pdf-lib 1.17.1、@pdf-lib/fontkit 1.1.1、Tesseract.js 7.0.0を固定。別Workerで解析・OCR・作成し、同梱の日本語モデル・CMap・フォントを使う。
- 再検証は独立PDF.js文書と作業タブのジョブで実行。native再読込と画素比較は作業タブに残り、比較中は一定行ごとに制御を返す。初期設計からの分担変更は[採用記録](decisions/pdf-execution.md)へ明示し、品質基準は維持する。
- 描画方針はビルド対象で固定。Chromiumと不明な開発対象はCPU経路、Geckoは固定PDF.jsのnative機能判定を使用。ビルド情報とmanifestの対象一致を検査し、UAによる分岐を使わない。
- PDFの回答と配置はrevisionで識別し、作成中の変更で古い出力を失効させる。バイト列をReactの表示stateへ保存せず、原本・出力はコントローラーのprivate参照で管理する。
- 保管庫はPBKDF2-SHA-256（通常600,000回、取込時は範囲を検証）、AES-256-GCM、独立nonce、チャンク1MiB、IndexedDBの原子的コミット。所有権をfenceし、放棄された所有者は生存確認で引き継ぐ。暗号化バックアップは分割保存・取消・別パスフレーズ取込に対応。
- 案内はECDSA P-256/SHA-256、鍵ID、canonical JSON、payload SHA-256。staging後に明示適用。最高到達releaseと撤回履歴は巻き戻さない。変更された公開鍵設定の競合を検出する。
- 開発時の最低Gecko版はmanifest上140。正式サポート表を確定したものではない。実ブラウザー検証にはWindows上のFloorp 12.20.1（Gecko157.0.1）、Firefox158 beta、Chromium149を用いた。
