# PDFの実行分担の採用記録

記録日：2026-10-13。製品設計の初期案では作成と再検証を一つの専用Workerの責務としていた。現実装の分担を明示し、機能と品質基準を実装場所から区別する。

PDF.jsの解析・文字取得・描画命令は同梱PDF.js Worker、文字認識は所有するTesseract Worker、PDFの作成・フォント処理・原本制約と配置の検査は作成Workerで実行する。帳票構造の推定、Canvasへの描画、生成物のnative再読込・値の照合、画素差分の比較は作業タブの検証ジョブに残る。出力文書は原本とは独立した、検証ジョブが明示的に所有する公式PDFWorkerで開く。

Canvasの実行経路はビルド対象で固定する。ChromiumはImageDecoderとOffscreenCanvasを無効にする経路、Geckoは固定PDF.jsのnative機能判定を使う。通常資料の初回資源量を減らすために採用し、UA文字列では分岐しない。両方をCPU経路にするとFloorpではかえって資源量が増えた比較結果を保持する。

差分計算は64行ごとにイベントループへ制御を返し、取消を確認する。検証に使うCanvasはページごとに解放する。native再読込や画素の取得を含むすべての同期区間がなくなるという保証はしない。原本の世代と回答revisionを固定し、途中の変更・取消・検証失敗では出力を登録しない。出力を再表示できる専用APIは成功して登録された実bytesの由来とhashを照合する。

検証ジョブは、初期読込だけでなくnative再読込・ページ・文字・描画命令・正常終了後の破棄待ちも取消で終了する。取消では所有Workerを同期終了し、独立文書の破棄を一度だけ開始する。応答しない破棄待ちにロック完了を依存させない。原本の破棄だけで検証文書まで停止したと扱わない。実PDFと公開APIの障害注入を使った8回帰の範囲は、追加の品質検証へ記録した。

この採用は、通常資料の768MiB、基準機の速度、100MiB／100ページ、取消表示1秒以内といった品質基準を緩和しない。測定は対象ブラウザー・ビルドhash・cold状態・測定機と関連付ける。検証ジョブ全体の専用Worker化は現実装の説明に含めず、応答性や資源量が未達なら、測定された同期区間を分離する追加実装の候補とする。

実機比較と、途中で発見した未達・修正は[追加の製品品質検証](../extended-validation.md)に保持する。現時点の開発機の結果を、指定基準機・人による監査・正式公開の合格と読み替えない。
