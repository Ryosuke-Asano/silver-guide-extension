# デモの進め方

2026年10月28日。PDFの検出・記入画面の起動・元欄への添付は、拡張側の汎用機能です。デモページの専用ボタン・メッセージ連携は取り除きました。

## 起動と操作

1. `dist-chromium/` をChromeの開発者モードで読み込みます。Floorp・Firefoxは `dist/manifest.json` を一時的なアドオンとして読み込みます。
2. `node demo/server.mjs` でフォームを起動し、`http://127.0.0.1:4187/` を開きます。4287番ポートでも起動できます。
3. 通常の名前・生年月日・住所・電話番号などを入力します。
4. E-mailの下の原本PDFリンクの横に、拡張が表示した「Silver Guideで記入」を押します。原本をダウンロード・アップロードし直す必要はありません。
5. 添付先を引き継いで、最初に「手続の内容」を選べます。「次へ」で氏名から順に入力し、最後の「入力を完了」で記入済みPDFを元フォームに戻します。
6. このデモのサイト用アダプターでは、通常の内容確認・模擬完了ボタンを拡張が順に操作し、完了画面を確認します。通常の入力に不足があればPDFを保持してエラーへ戻ります。

通常サイトでは添付までが既定です。送信操作を希望する場合は、記入画面上部のボタン名と選択欄を確認します。複数の添付先は選択でき、添付欄がないページはPDFとして保存できます。設計と制約は[PDF連携の設計](decisions/pdf-web-workflow.md)を参照してください。

## 文章の説明と、単独のPDF記入

フォームの言葉や案内文を選び、拡張アイコンからサイドパネルを開きます。「在住」などの単語は、言葉と説明文だけを中心に表示します。文章では「文章のポイント」を先に表示し、「言葉の意味」と「原文を見る」は必要なときに開けます。パネル内のロゴ・ページ名・重複見出し・常時の補足説明は取り除いています。

サイドパネル右上の「⋯」→「PDFを開く」から単独で開いたPDFは、「ここまでの入力を保存」、または最後の「PDFを保存」で保存します。元サイトのダウンロード・ファイル選択もそのまま使えます。

## PDFの記入欄

記入画面の上部は「PDFに記入」とファイル名のヘッダー、添付先・完了後の操作の行にまとめました。連携元のURLとデモ用の補足は、右上の「書類の詳細」から開けます。入力欄とプレビューは、その直下から表示します。

このデモと同じ原本PDFに、位置を確認した14項目を用意しています。最初の「手続の内容」には新規登録・登録内容変更・登録更新・紛失・臨時貸出・その他の6つのチェック欄があります。左の選択欄でもPDF上の枠でも付け外しでき、複数の選択も保持します。その後は氏名・フリガナ各2欄、郵便番号2欄、住所1欄、自宅電話・携帯電話各3欄です。生年月日、在勤・在学先などは、この14項目に含みません。元の紙面で確認してください。

採用条件は原本のSHA-256が `cd6ad4a7291340abcc8c70b94c191367ce1b9fa4c01a604889c5c9a4d6b01ff7` と一致することです。ファイル名を変えても使えます。記入済みPDF、入力欄追加版、改訂版、別のPDFは通常の読み取りを使います。原本に変更や保存制限を加える処理はありません。位置の出典は `demo/assets/library-application-source.json`、実装は `src/data/demo-pdf-layout.ts` です。

この14項目はデモ用に人が設定した位置です。汎用の自動認識精度の測定結果には数えません。原本の必須条件は未判定のままです。紙面にない必須条件や氏名の文字数制限を追加しません。

## 共通の操作改善

- 項目は「戻る／次へ」で順に移動し、入力内容を保持します。
- 単独で開いたPDFは、最後の項目まで進む前に保存できます。入力した値の形式・文字数・位置の検証は途中保存にも適用します。
- 保存後に編集すると「未保存の入力があります」に戻り、前回の保存通知を消します。狭い画面では通知を操作欄に重ねません。
- 選択文の説明は、文章のポイントを先に表示します。辞書では元の単語と説明を併記し、短い言い換えの重複見出しは省きます。数字・否定・条件を含む原文をそのまま確認できます。
- 新しい文章を選ぶと、説明のスクロール位置と折り畳みをリセットします。

## 確認範囲

Mac版Chrome 156の実拡張を使い、デモと異なる4388番ポート・異なる要素名の通常フォームで、ページ側の専用連携なしの検出・取り込み・添付を確認しました。送信操作の選択、標準の入力検証、複数の添付先、他の添付ファイルの保持、別オリジンのPDF、MIME指定の配布URL、添付欄がないPDF、送信先変更時の停止、サービスワーカー再起動後の継続も確認しています。同一オリジンのセッションは維持し、別オリジンの配布元へ認証Cookieを送らないことを確認しました。

1440×960と420×920で表示を確認し、ファイル選択ダイアログ・ダウンロード・ネットワーク書き込み・コンソール／ページエラーは0件でした。図書館デモも、ページ側の専用コードを取り除いた状態で模擬完了まで確認しました。Floorpはビルド・パッケージ検査までで、今回の汎用連携の実機確認は含めません。
