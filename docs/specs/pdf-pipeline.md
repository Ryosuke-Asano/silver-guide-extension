# Silver Guide PDF 処理仕様

> 2026-10-14 PDF入力導線の改訂：標準画面は左に単一の入力欄・短い説明・戻る／次へ、右に原本を常時表示する。読み取り後すぐに入力でき、最終項目の「PDFを保存」で検証と保存を連続実行する。推定した記入者・必須性・ページ判断を確認済みに書き換えない。編集専用の inputMode=direct で意味確認の必須工程を省き、回答型・原本の不変制約・記入位置・文字数・出力再検証は維持する。下書き・補正はメニューから利用し、従来の詳細編集は任意の経路として残す。下記の従来確認工程は標準入力の必須手順ではない。


本仕様は [製品設計](../product-design.md) の SG01〜SG06、SG12、SG13 を実装する契約である。PDF の意味を正しく把握したことと、文字認識に成功したことを区別する。製品の汎用 PDF 対応は、解析、項目確認、手動修正、回答、対応形式の書き出しを一つの経路として提供する。

## 1 能力判定と対応表

取り込み直後に `read`、`analyze`、`nativeWrite`、`overlayWrite`、`export` の可否と理由を判定する。単一の成功フラグを使わない。PDF.js で表示できることは pdf-lib で再保存できることを意味しない。

| 文書 | 読み取りと解析 | 書き出し方針 |
| --- | --- | --- |
| 暗号化のない標準 AcroForm | 入力欄と widget、文字、説明を解析 | 既存の値と appearance を更新 |
| 入力欄のない文字 PDF | 文字と構造から欄を推定 | 元のページに文字や印を重ねる |
| スキャンと混在 PDF | ページ・領域単位で OCR と構造解析 | 元ページの画像を残して記入を重ねる |
| 署名用の空欄がある PDF | 署名欄を入力対象から除外し、ほかの欄を解析 | 署名・押印の実行を伴わない部分だけ記入 |
| 電子署名済み PDF | 署名の存在を示し、読み取りと説明に限定 | 標準版では変更した PDF を作らない |
| 暗号化 PDF | 対応する暗号方式でパスワードを入力した場合、閲覧と解析 | 標準版の記入と再保存は不可 |
| XFA | 利用可能な静的表示を説明に使う。表示不能なら外部ビューアを案内 | 動的フォームの記入と再保存は不可 |
| 編集権限が制限された PDF | 許される閲覧・抽出の範囲を表示 | 制限を迂回して記入しない |
| 破損 PDF | 読めるページと失敗を区別 | すべての出力契約を満たせない文書は保存しない |
| 上限を超える PDF | 受付時に容量・ページ・画像の上限を表示 | 小さいファイルで再受付する |

署名の存在検出は署名者の本人確認や証明書の正当性検証ではない。署名を保持して変更できると表示しない。読み取り専用の文書を無断で画像化し、同等の編集可能文書として保存する迂回経路も提供しない。

AcroForm の計算、書式、検証が JavaScript 等のアクションに依存する場合は、影響する欄を能力判定で検出する。確認済みテンプレートに同等の制限された宣言的規則がある場合だけ、その規則で結果を再計算・検証する。置き換えられない場合は、本人が値を確認した印刷用出力に限定するか、記入を不可にする。機能を除去したまま電子提出用の編集可能フォームとして成功表示しない。出力前に失われる機能と影響欄を示す。

pdf-lib は暗号化 PDF をサポートせず、`ignoreEncryption` は復号手段ではない。XFA の欄にも対応しない。これらは採用する出力エンジンの制約として能力判定に反映する。[暗号化の制約](https://github.com/Hopding/pdf-lib#encryption-handling)、[フォームと XFA](https://pdf-lib.js.org/docs/api/classes/pdfform)

## 2 取り込みと不変の原本

入力経路は File、ドラッグ投入、明示操作による HTTP と HTTPS の PDF 取得とする。取得リンク、リダイレクト、Content-Type、バイト列、ページ数、暗号化、署名、フォーム、アクション、編集権限を検査する。Content-Type や `.pdf` という拡張子だけで PDF と判断しない。認証画面の HTML を取得した場合は区別する。

原本は不変の Blob と SHA-256 の組として保持する。URL、ファイル名、ハッシュも個人の作業情報として扱い、ログや更新配信元へ送らない。PDF.js の Worker へ渡す配列には原本から作った専用のコピーを使う。Worker 転送で ArrayBuffer の所有権が移る場合も、原本を失わない構成にする。[PDF.js API](https://mozilla.github.io/pdf.js/api/draft/api.js.html)

暗号化 PDF のパスワードは、読み取りの所有セッションでのみ使用する。下書き、URL、診断、テンプレートへ保存しない。ロック時には文書とともに破棄し、再開時に再入力する。

作業の回答、項目対応、手動修正は原本と別に記録する。再出力は必ず原本から再構築し、前回の記入済み PDF に追記を重ねない。元ファイルは上書きせず、記入済み PDF を別の保存物にする。

## 3 ページと座標の契約

標準座標は回転前の PDF user space の左下原点とする。PDF の座標単位をそのまま保持し、`UserUnit` の物理換算は viewport の変換で一度だけ扱う。MediaBox、CropBox、可視領域の原点、回転、UserUnit、ページ参照を保存する。

OCR 用画像、傾き補正、切り出し、画面上の表示はそれぞれの変換行列を持つ。OCR 画像から PDF の座標への逆変換を保存し、四隅の Quad と矩形の両方を扱う。`pageHeight - y` だけで上下を反転する変換を使わない。

変換の契約は `PDF 座標 → viewport → 切り出し画像 → 傾き補正画像` とその逆である。すべての変換は行列と適用順序を明示し、逆変換できない領域を自動記入へ使わない。回転 0、90、180、270 度、非ゼロ CropBox、UserUnit の異なる資料で往復誤差を検証する。

既存フォーム欄には完全な欄名、オブジェクト参照、widget 参照を保持する。同じ回答が複数 widget に現れる場合は一つの意味上の質問と複数配置として表す。選択肢も複数ページや widget の配置と native field の参照を持つ。同名でも別の記入者・意味を持つ推定欄は別の ID にする。

出力層では文字サイズ、行間、余白、印の太さ等の物理 pt を raw PDF 座標へ変換する。`fontSizeUser = physicalPt / UserUnit` を含め、入力座標の変換と出力の物理寸法を別々に検証する。UserUnit に対応していない出力 API はアダプターで補正し、補正できない場合は書き出し能力を不可にする。

## 4 解析パイプライン

1. 文書の能力判定を行い、原本、エンジン版、文書 revision を固定する。
2. 全ページの文字、注釈、既存欄、画像領域、罫線と可視領域を取得する。
3. ページ・領域ごとに native text、画像、既存 OCR 層の品質を判断する。
4. 必要領域を描画し、傾き補正、領域分割、OCR を行う。
5. OCR 結果を標準座標へ戻し、native text との重複と不一致を整理する。
6. 記入枠、下線、マス目、表、チェック枠、選択肢、ラベルから欄候補を作る。
7. 近接だけでなく、見出し、表の行列、説明文、欄型、記入者のまとまりを使って対応付ける。
8. 確認済みテンプレートが合う場合は対応候補を補強し、版の一致を検証する。
9. 本人が原本と質問を照合し、不確かな欄を確認し、欠落や誤対応を修正する。
10. 回答と位置を固定した出力スナップショットを作り、出力と再検証へ進む。

文字が少し取得できるだけで、そのページ全体の OCR を省略しない。文字見出しとスキャンされた表が混在する資料、誤った既存 OCR 層、画像の中だけにある説明に対応する。重複判定は位置、文字、方向、内容の類似性を用い、矛盾は片方を黙って削除せず根拠に残す。

Tesseract.js は PDF を直接解析しない。描画された画像を入力し、文字位置を含む出力を明示して取得する。[Tesseract.js の範囲](https://github.com/naptha/tesseract.js)、[OCR API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)

構造解析は罫線や空白の検出、文字ブロック、説明と枠の関連を扱う。レイアウト認識モデルを導入する場合は同じ候補と根拠モデルへ出力し、モデルが選んだ座標を直接書き出しに使わない。OCR、構造規則、モデルの版を別々に記録する。

## 5 欄の意味と確認

各欄に原文ラベル、短い説明、記入者、欄型、選択肢、必須の根拠、記入位置、条件、出典を持たせる。記入者は本人、代理人、所属組織、役所、署名、未確認を区別する。推定から生年月日、氏名、住所等の本人情報を創作しない。

必須は `true`、`false`、`unknown` の三値とする。空欄であること、枠線があること、OCR の強調表示だけで必須にしない。原書類の条件と確認済みのテンプレートの根拠を表示できる場合だけ確定する。

記入可能な対象欄の`unknown`は、共通検証と実際の出力検証で`REQUIRED_UNCONFIRMED`として拒否する。空欄、回答の保留、条件不成立、未記入のまま出力する選択で、この確認を省略しない。原本指定の読み取り専用欄と、本人が対象外にした欄は既存の境界を保ち、回答・原本・履歴を消さない。記入工程から未確認の欄へ戻った場合は確認工程を開く。記入者の変更も、意味と場所の新しい確認を必要とする。

同意、宣誓、署名、押印、本人と代理人の区別、役所の記入欄は特別な扱いをする。同意と宣誓は本人が原文を確認して選択する。署名・押印は入力対象外とし、役所欄は除外する。記入者が未確認の欄は確認を経るまで回答の転記を許可しない。

確認済み様式との完全一致、本人が確認した欄、自動推定の欄を表示で区別する。汎用文書では全ページを一覧でき、「このページの欄を確認した」「入力欄はない」「今回は対象外」を記録する。単に検出した欄数だけを見せて、検出漏れの確認を省略しない。

### 5.1 信頼度

文字認識、座標、ラベル対応、欄型、記入者、必須・条件を別のスコアとして持つ。未評価のスコアは `null` とし、0 または 1 に置き換えない。生の OCR スコアを正解確率として表示しない。

校正された評価器が「自動候補の精度」という品質条件を満たす場合だけ、通常の質問として提案できる。不一致、複数候補、校正範囲外のレイアウトや画像品質、未校正の評価器は原画像とともに要確認へ送る。テンプレート未登録であっても、校正対象の構造と品質に属する欄は自動候補になれる。数値しきい値はバージョン付きの校正プロファイルで管理し、恣意的な 0.8 等を正確性の保証にしない。

高いスコアも本人の全体確認を省略する根拠にはしない。特別な欄の扱いはスコアより優先する。品質評価では自動提案した割合、要確認の割合、見逃した欄も公開判定に含め、すべてを要確認にすることで高精度を装わない。

### 5.2 手動修正

原本のページから欄を追加し、ラベル、型、位置、順序、記入者、選択肢、条件を修正できる。枠の候補選択と数値入力を持ち、ドラッグを唯一の操作にしない。修正は履歴を持ち、取消と再適用を提供する。

再解析は確認済み欄と回答を保護する。新しい解析結果を差分候補として扱い、本人が採用した場合にだけ mapping revision を更新する。更新によって影響する回答、プレビュー、出力の確認は無効化して再確認する。

## 6 回答と日本語レイアウト

保存する回答は本人が入力した元の値と、確認して採用した表示形式を分ける。氏名の旧字体、異体字、全角、空白を無断で変更しない。和暦・西暦、郵便番号、電話番号、ふりがな、全角・半角の変換には変換後のプレビューと取消を提供する。ふりがなを氏名から確定生成しない。

レイアウト層は横書き、縦書き、複数行、マス目、日付の分割、表の行、チェック欄を扱う。マス目の文字数は書記素やコードポイントの扱いを定義して数え、結合文字と異体字セレクターを切り離さない。一方、native の MaxLen と出力エンジンの長さ判定は別に保持する。採用するエンジンが UTF-16 のコード単位で長さを判定する場合は入力段階で両方を検証し、元の制約を無断で解除しない。旧字体等が native 制限で書き込めない場合は、理由と対応する出力方式を本人へ示す。[pdf-lib の欄への設定](https://github.com/Hopding/pdf-lib/blob/v1.17.1/src/api/form/PDFTextField.ts)

日本語の文字が使える再配布可能な静的フォントを同梱する。使用文字の glyph coverage を検査し、不足する文字を空白や別の漢字へ黙って置き換えない。日本語フォームの appearance 更新にも対応フォントを渡す。pdf-lib の既定の WinAnsi フォントだけでは日本語を扱えない。[PDFForm のフォント更新](https://pdf-lib.js.org/docs/api/classes/pdfform)

幅、高さ、行間、余白、禁則、縦書きの字形を測定する。自動縮小の下限は PDF 上 10pt を初期の品質基準とし、それ以下を必要とする欄は修正を促す。原様式の指定サイズが小さい場合は、元の欄寸法、指定サイズ、拡大プレビューを示し、確認済み様式の例外または本人が選んだ欄単位の例外として記録する。自動で小さくした結果と、本人が原様式に合わせて確認した結果を区別する。長い住所が収まらない場合に、書類の意味を変える省略や別ページ追加を自動実行しない。

## 7 出力と検証

出力スナップショットは原本ハッシュ、回答 revision、mapping revision、採用したテンプレート、エンジン、フォント、出力設定を固定する。スナップショット作成後に入力が変わったら、その出力を現在の回答の完成物として扱わない。

既存 AcroForm には欄の値と appearance を更新する。推定欄には元ページへ文字と印を描く。紙提出用は確認後にフォームの appearance を固定できる。編集可能な出力と印刷用出力は区別する。電子提出先が編集可能なフォームを必要とする場合、固定化を既定にしない。平面 PDF に重ねた文字は、元から入力欄を持つ PDF と同じ編集性を持つとは表示しない。

出力ではページ数、ページの箱、回転、元の画像と本文、必要な静的注釈を維持する。能動的な処理として、文書と注釈の JavaScript、OpenAction、追加アクション、Launch、SubmitForm、ImportData、埋め込みファイルの起動を構造的に除去する。HTTP と HTTPS の通常リンクは別の許可された扱いにする。処理はオブジェクトグラフで行い、文字列検索を除去の根拠にしない。対応していない構造を検出した場合は出力を止める。この処理を任意文書の完全な無害化保証として宣伝しない。

生成した PDF bytes を新しい PDF.js インスタンスで再読み込みし、実際の bytes から最終プレビューを作る。UI に回答を重ねただけの仮プレビューを最終結果として扱わない。PDF 内の値、ページと配置、glyph coverage、文字のはみ出し、選択印、変化してはいけない領域を検査する。

ラスタ差分は配置の補助検査に使い、フォントのレンダリング差を校正する。ラスタ一致が制度上の正しさや署名保持を証明すると解釈しない。検証失敗には原因と該当欄を示す。未解決の誤配置を含む出力は通常の保存対象にしない。

本人が確認した bytes の SHA-256 を記録し、その bytes そのものを保存する。保存直前に生成し直さない。PDF の作成成功、検証成功、ファイル保存の成功を別の状態として記録する。保存失敗では検証済み bytes を維持し、再試行できる。

## 8 Worker と資源管理

PDF の取得・描画、OCR、構造解析、出力・再検証をジョブとして管理する。各ジョブは `jobId`、`documentId`、`revision`、`generation`、`pageId`、`engineVersion` を持つ。古い世代の完了結果を破棄する。

標準では OCR は 1 Worker とし、基準を満たした端末だけ最大 2 Worker にする。描画済み画像の同時保持は原則 2 領域に限り、処理済みのビットマップと ArrayBuffer を解放する。OCR は 300dpi 相当を初期値とし、大きいページは領域やタイルに分ける。全ページを先に画像化しない。

最大受付は初期の設計上限として 100MiB、100ページとする。1領域の描画は最大 16メガピクセル、ページ全体の画像はタイル処理を利用する。埋め込み画像のデコード寸法にも上限を適用する。これらは製品の限界値として表示し、実測によって変更する場合は仕様と試験を同時に更新する。

外部から受け付ける原本と、アプリが検証して生成した記入済み出力の上限を区別する。100MiBの原本へ文字・フォント・appearanceを追加すると出力は100MiBを超え得るため、生成・再検証・内部プレビューの出力上限は160MiBとする。これは外部PDFの受付上限を広げる指定ではない。内部プレビューは同じ原本セッションが正常に検証した出力の記録だけを受け付け、原本hash、出力hash、サイズと出力bytesの再計算hashを照合する。未登録の出力、偽装・改変・別原本の結果、160MiB超過を拒否し、ページ数・画像の上限と能動的処理の制約も維持する。生成物を新しい外部ファイルとして取り込む際には通常の100MiB制限を適用する。

ページ単位の解析チェックポイントを持つ。キャンセルはキュー停止、描画取消、必要な Worker の終了を行い、待っている Promise を管理層で必ず完了または reject する。ライブラリの `terminate()` だけに完了処理を委ねない。Worker のクラッシュとタイムアウトでも同じ契約を適用する。

ページの処理が初期 90秒を超えた場合は延長または中止を選べる表示にし、無制限に待ち続けない。自動再試行は同じページで最大 1 回とし、失敗が続く場合は未解決として保持する。取消の操作は 1秒以内に UI へ反映し、後続の結果を採用しない。

文字認識が時間切れになったページには、未解析として保留する方法と、本人が上限を180秒へ延長して最初から再解析する方法を示す。終了した認識処理を途中から再開したと表示しない。複数の画像領域があるページでも認識の待ち時間を領域ごとにリセットせず、そのページの共通予算から残り時間を使う。再解析結果は差分として確認し、既に確認した対応と回答を自動で置き換えない。180秒で失敗した場合も自動で再延長せず、本人が再試行・修正・保留を選ぶ。

PDF.js の本体と Worker、CMap、標準フォントと必要な WASM は同じ固定版を使う。Tesseract の Worker、core、日本語言語データ、出力フォントも同梱し、パスを `runtime.getURL()` から渡す。外部 CDN の既定パスを残さない。Blob Worker を使わない構成を優先し、MV3 の CSP と実機で照合する。[WebExtension CSP](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/content_security_policy)

## 9 実装前に固定する契約

- 採用版で利用できる API、署名の存在検出、暗号化と権限判定、破棄処理。
- native text と OCR の品質判定、構造候補、校正プロファイル。
- 日本語フォントのライセンス、対象 glyph、縦書きとマス目のレンダリング。
