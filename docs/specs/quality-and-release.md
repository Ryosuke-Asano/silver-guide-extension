# Silver Guide 品質と配布仕様

本仕様は [製品設計](../product-design.md) の SG01〜SG14 の公開条件を定める。数値は設計上の達成目標であり、2.0の測定結果ではない。実装と検証の現状は[実装状況](../implementation-status.md)と[検証記録](../verification.md)に記録する。任意 PDF の処理を後続版へ移して公開条件を満たしたと扱わない。

## 1 合否の原則

機能、文書種別、環境を分けて結果を残す。確認済みテンプレートの結果と汎用解析の結果を混ぜない。非対応形式を正しく検出したことを、記入成功へ数えない。未解決を要確認へ送れたことと、本人が記入済み PDF を完成できたことも別の指標にする。

データ喪失、無断の外部送信、誤った記入者や記入位置を完成として扱う問題、主要操作を妨げるアクセシビリティの問題、重大なセキュリティ上の欠陥が残る版を公開しない。通常ケースだけの成功や型検査の成功を製品の品質確認に代用しない。

## 2 検証書類

最低 300 PDF、5,000 以上の欄を持つ評価資材を整える。公開資料と作成した試験資料を使い、実在する個人の記入済み書類を既定の資材にしない。利用条件、取得日、版、正解を管理する。

構造・推定規則の調整用と公開判定用を、自治体、様式系列、改訂時期で分ける。ページだけを分けて同じ様式を両側へ入れない。公開判定用は最低 100 PDF、2,000 欄とし、調整で参照した場合は判定用から外す。

| 軸 | 必須の資料 |
| --- | --- |
| PDF 種別 | AcroForm、文字 PDF、画像 PDF、既存 OCR 層、混在ページ |
| 位置 | 4方向の回転、傾き、非ゼロ CropBox、MediaBox の相違、UserUnit |
| 日本語 | ふりがな、和暦、旧字体、異体字、結合文字、縦書き、マス目 |
| 欄の意味 | 本人と代理人の同名欄、所属、役所欄、署名、同意、条件付き欄 |
| 構造 | 複数列、表、反復行、欄のないページ、別紙、注記、複数 widget |
| 画像 | 低解像度、罫線のかすれ、影、ノイズ、写真撮影、文字と画像の混在 |
| PDF 制約 | 暗号化、編集権限、電子署名、XFA、破損、過大画像、アクション、埋め込みファイル |
| 出力 | 長い住所、チェック印、複数ページ、足りない glyph、欄の計算と検証 |

正解には文字列、ページ、Quad、欄型、ラベル、記入者、必須の根拠、条件、選択肢、除外欄、元 PDF と期待される出力を持たせる。意味のラベルは二者で確認し、不一致を解決する。対象外の手書き文字等を評価対象から除く場合は分類と件数を記録し、良い部分だけを平均しない。

## 3 解析の品質目標

| 指標 | 設計目標 | 測り方 |
| --- | --- | --- |
| 確認済み様式の必須欄、記入者、配置 | 検証資材上の誤り 0 | 各対応版と境界ケースを正解と照合 |
| 汎用欄の検出 | precision 95%以上、recall 95%以上 | 文書種別ごとに欄の対応と配置を照合 |
| 高信頼として自動提案したラベルと位置 | precision 99.5%以上、片側95%信頼下限 99.0%以上 | 校正に使っていない欄で評価 |
| 自動提案の割合 | 正解資材上の対象欄の 60%以上 | 検出漏れを含む全対象欄を分母にし、要確認の割合と併記 |
| 本人、代理人、役所の確定対応 | 検証資材上の取り違え 0 | 未確定と取り違えを別に計数 |
| 印刷された日本語 OCR | 良好スキャンの CER 2%以下、劣化資料は 5%以下 | 数字、氏名の例、条件の誤りも個別集計 |
| 座標 | 往復誤差 0.5pt 以下、出力配置ずれ 1pt 以下 | 物理単位へ換算し回転と箱を含めて評価 |
| 未確認・未解決の表示 | 黙った欠落 0 | 全ページの状態と検出漏れを人が照合 |

欄の一致は同じ意味の正解 ID と位置の両方で判定し、位置は必要に応じて IoU を補助に用いる。自動提案率は欄単位で数え、文書ごとの割合の分布と、種別・記入者別の結果を併記する。簡単な一欄だけを提案した文書を自動化成功と数えない。

精度の点推定は全対象提案を使い、区間は文書と様式系列の相関を考慮する。文書単位の層別 bootstrap 10,000 回と、別々の様式系列から事前規則で一提案ずつ選んだ監査標本の片側95% Clopper–Pearson 下限を報告し、保守的な方で判定する。誤りがない場合も標本が小さいことによる不確実性を無視しない。必要な独立標本数を算出し、最低資料数で足りなければ判定資材を追加する。

OCR の CER は文字誤り率であり、氏名や数字に対する安全性の保証として扱わない。高信頼のサンプル数が足りない区分は、達成した精度を表示せず要確認の区分に留める。すべてを要確認へ送って自動提案の品質を達成したと扱わない。

テンプレート、汎用の文字 PDF、画像 PDF、混在 PDF で別に集計する。低品質で自動化できない資料でも、読めない箇所が表示され、修正や保留へ進めることを評価する。基準未達であることを理由に汎用処理そのものを製品公開範囲から外さない。

## 4 文章説明と読書の品質

説明の評価資材は最低 200 の文または段落とし、条件、否定、例外、期限、費用、地域、本人と代理人を含める。原文から根拠範囲を示し、説明成功、原文だけの表示、対応不能を別に集計する。

確認済みの標準手続き資材では 95%以上、汎用の行政文章の判定資材では 80%以上に、実際の結論・条件・行動の整理を提供することを設計目標とする。対応不能を説明成功と数えない。制度条件、数字、否定、例外を変更する誤りは判定資材上 0 を要求する。

読書表示は見出し、表の見出しとセル、リスト、リンク先、脚注の参照を照合する。抽出されない重要な領域を知らせる。読み上げは日本語音声、localService の判定、voiceschanged、停止と再開、段落移動、長文、声がない環境を試験する。標準版がリモート音声へ切り替わらないことを通信面でも確認する。

## 5 PDF 出力の検証

テストは画面上の仮プレビューではなく、保存対象の PDF bytes を再読込して行う。次をすべて確認する。

- ページ数、ページの箱、回転、元の本文と画像が契約どおり維持される。
- native 欄の値、appearance、複数 widget、チェックと選択値が合う。
- 日本語の glyph が存在し、氏名、住所、ふりがな、日付、異体字が欠けない。
- 文字が指定枠へ入り、不要な縮小、重なり、欠落がない。
- 記入者、欄条件、役所欄、署名欄、同意の扱いが合う。
- アクション除去の影響を検出し、計算や検証に依存するフォームを誤って電子提出可能と表示しない。
- 能動的なアクションと埋め込み処理が出力契約に従う。
- 元ファイルが変更されず、確認した hash の bytes が保存される。

native 値の比較、文字と字形の検査、geometry、画像差分、本人の最終確認を組み合わせる。画像差分の許容値はレンダリング環境を固定して校正し、対象欄以外の差分も調べる。意味の適合を画像だけで判定しない。

Floorp と Firefox のビューアで再表示し、少なくとももう一つの独立した PDF ビューアでも日本語とフォームの表示を確認する。印刷用は A4 など元様式の用紙条件で試験し、ページの拡大縮小がチェック欄の位置を変えないことを確認する。電子提出用は対応する提出基盤の公開仕様と試験用経路がある場合だけ、その互換性を保証対象にする。

## 6 アクセシビリティと利用者試験

拡張機能が提供する画面を WCAG 2.2 AA の基準で検証する。自動検査に加え、キーボード、NVDA、200%文字拡大、400%ズーム、高コントラスト、動きを減らす設定、日本語 IME を手動確認する。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)

PDF の位置修正もドラッグだけに依存しない。ラベル、ページ、候補、数値位置の操作を読み上げで識別できることを確認する。画像の意味が読み取れない箇所は未解決として表し、支援者と確認する画面に引き継げることを試験する。操作へのアクセスと原画像の意味を独力で把握できることは区別する。

初期の公開判定では、60歳以上を含む対象利用者を最低 12 人、キーボードや読み上げを常用する人を別途最低 4 人含める。架空の情報で、PDF 取り込みから確認と保存、下書きの再開、文章説明、チェックリスト、対応ウェブフォームを試す。必要な試験同意とデータ削除を定める。

対応する通常文書で 90%以上が操作の直接指示なしに正しい PDF 保存を完了することを目標とする。件数と信頼区間、誤り、要した支援を記録する。低品質文書では正しく保留し、未解決を認識できることも評価する。小さい試験の割合を全利用者の保証として宣伝しない。

## 7 性能と資源の予算

基準機は Windows のサポート中の版、4コア相当 CPU、8GiB RAM、SSD、1080p 表示、ハードウェア描画の有無を記録した実機とする。Floorp と採用したエンジン版、OCR キャッシュの有無を固定する。速い開発機だけの測定にしない。

| 対象 | 設計目標 |
| --- | --- |
| ポップアップと開始操作 | p95 1秒以内に操作可能 |
| 質問入力と次項目 | p95 100ms 以内に反応 |
| 取消の UI | 1秒以内に中止状態を示す |
| 5ページの文字 PDF | p95 5秒以内に項目確認へ進める |
| 良好な A4 スキャン 300dpi | OCR と構造解析を p95 12秒以内／ページ |
| 10ページのスキャン PDF | p95 120秒以内に解析が完了する |
| 10ページの出力と再検証 | p95 15秒以内 |
| 保存 | 入力後最大 5秒以内のコミット、容量不足を明示 |
| 作業の増分メモリー | 10ページ標準資料でピーク 768MiB 以下 |

受付上限の 100MiB と 100ページは別の負荷試験とする。全ページを画像化せず、ページ数に比例して画像キャッシュが増えないこと、上限付近でも取消と保存ができることを要求する。大きい文書の時間は個別に記録し、上記の通常文書の時間へ含めて平均をよく見せない。

達成していない数値を製品案内へ掲載しない。実装評価によって基準を調整する場合は、理由、測定、対応上限、UX の変更を採用記録へ残してから仕様を更新する。

## 9 保存と境界の試験

容量不足、IDB transaction 中断、暗号化中断、キー変更失敗、Worker と作業タブの停止、ブラウザー終了、未保存編集、複数タブ、時計の変更、旧形式の復元、破損バックアップを試す。バックアップの過大な KDF 回数、サイズ、チャンク数、誤った nonce と tag、圧縮展開、取消も検査する。保存済み revision が失われず、保存していない内容は保存済みと表示されないことを合否とする。

ネットワーク、storage、IDB、拡張メッセージ、コンソール、診断の各経路を調べる。原 PDF、OCR、回答、URL、ファイル名、鍵、パスフレーズが意図しない場所へ出ないことを確認する。標準処理はネットワークを遮断した環境でも完了する。更新と本人が選んだ診断以外の通信を行わない。

悪意ある PDF、巨大画像、HTML の項目名、誤ったメッセージ送信元、サイズ超過、改ざんした更新、古い署名済み更新、任意式を含むガイドを検証する。対応外の入力は明示的に拒否し、検証失敗で弱い経路へ切り替えない。

## 10 配布と互換性

Firefox 系は MV3 WebExtension を署名して配布する。公開 ID は既存公開物の有無を確認して固定し、更新では保持する。開発用・試験用・製品用を区別し、試験版が同じ保管庫を無断で更新しない。配布には AMO 掲載と署名済み自己配布のどちらを使うかを採用記録で確定する。[ID と更新](https://extensionworkshop.com/documentation/develop/extensions-and-the-add-on-id/)、[自己配布](https://extensionworkshop.com/documentation/publish/self-distribution/)

Floorp の正式サポート版と直前のサポート版、対応 Firefox、OS、署名、CSP、WASM、Worker、IndexedDB、download、音声、optional host permission、データ収集同意を試験する。最低 Firefox 版を決めるときは Floorp の実際の API と配布方針を照合する。開発用の一時読込成功だけで正式配布の互換性を判断しない。

ブラウザー本体の署名済み更新と、辞書・様式のデータ更新を分ける。コード、WASM、実行に必要なモデル、フォントの採用版はビルド入力とし、実行時 CDN を使わない。再現可能なソース、依存資産一覧、ハッシュ、再配布条件を残す。[Mozilla のアドオン方針](https://extensionworkshop.com/documentation/publish/add-on-policies/)

配布に必要な利用者向け情報は、機能と制約、対応環境、プライバシー、権限の理由、保管庫と削除、パスフレーズ紛失、ライセンス、問い合わせ先、更新履歴とする。問い合わせ用の資料を本人の操作なしに送信しない。

## 11 データ更新と保守

データ更新には ECDSA P-256 等の検証済みの署名方式を使い、正規化した manifest にリリース番号、資材 hash、schema、対象 app 版、有効期間、撤回とロールバック指示を含める。採用方式と正規化方式を固定し、異なる実装で署名結果を照合する。

通信は専用の公開 origin に限定する。署名、hash、schema、サイズを検証して staging へ保存し、まとめて昇格する。`activeRelease` と `highestSeenRelease`、撤回リストを分け、復旧でも最高到達番号と撤回情報を後退させない。普通の更新はリリース番号を後退させない。

ネットワークからのロールバック指示は、新しいリリース envelope に採用する旧 payload の hash を明示した署名付き指示として受ける。端末内の最後の正常版への復旧も既知の撤回版を除外する。全候補が撤回されている場合は対象の詳細支援を停止し、古い署名済み応答を正常な更新として再受入しない。

署名鍵の管理役とガイド編集役を分け、公開前に二者で変更を確認する。信頼公開鍵の変更には既存の信頼から認証できる更新を用い、鍵の漏えい時はアドオン更新経路も含めて復旧する。秘密鍵を拡張配布物へ含めない。

リンク切れ、ガイド期限、様式改版は公開時と更新時に確認する。確認済みガイドは少なくとも90日ごとに再確認し、有効期限のある手続きはその期限に合わせる。変更のない PDF の座標を、似た新様式へそのまま移さない。利用者の訂正報告は対象を本人が確認して送る。

診断は既定で送信しない。送信機能を提供する場合は明示操作とブラウザーのデータ収集同意を照合する。自動の内容収集を製品改善の条件にしない。公開後の問題は分類した件数と再現用の匿名資料から検証する。

## 12 公開判定と障害対応

公開判定の責任は、製品仕様、PDF と解析、アクセシビリティ、データ保護、配布と保守の役割ごとに記録する。同じ人が複数役を持つ場合も、独立した確認が必要なガイド公開と重大変更の確認を省略しない。

公開前に、すべての SG 要件、corpus の結果、実機表、利用者試験、保存復旧、署名済みパッケージ、通信、ライセンス、サポート、ガイド更新、保管庫形式の互換性を確認する。達成していない公開条件を将来の作業として残したまま製品完成と宣言しない。

誤配置、機密情報の無断移動、保存済みデータの喪失が見つかった場合は、原因に関係する機能やガイドの配布を止め、原本と下書きを保持した状態で修正と復旧を案内する。データ更新で直せる問題とコード修正が必要な問題を分ける。復旧では旧 app と新保管庫の互換性を確認し、単にパッケージを旧版へ戻して上書きしない。
