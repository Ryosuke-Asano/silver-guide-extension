# Silver Guide 3.0.0 実装作業順

更新日：2026-10-20 JST。対象：[製品 Spec](spec.md)・[画面仕様](screen-design.md)。この順で3.0.0を実装する。現在の完了範囲・検証・公開条件は [実装状況](implementation-status.md) を参照する。

## 1. 実装の到達点

- フォーム：元の入力欄へのフォーカスで、欄の**上側に Tooltip**。上が使えない場合のみ下へ出し、横には出さない。別入力画面・追加ボタン・反映工程は作らない。
- 文章の解説：本文の同梱辞書語へ下線を付け、クリック・Enter／Spaceでページ内の短いポップアップを表示する。操作は閉じる一つ、Escape・外側クリックにも対応。長い文章の範囲選択はサイドパネルを補助として残す。三機能の切替タブや機能選択用の中間ポップアップを作らない。
- PDF：専用タブの左に質問、右に自動の記入プレビュー。一問ずつ「戻る／次へ」で全回答を保持し、最後に「PDFを保存」。入力・修正・削除を保存前に確かめられるようにし、更新ボタンは追加しない。作成・検証・保存を一続きにする。
- 独自パスワード保護・保管庫・下書き・履歴・バックアップ・登録情報・別 Reader・読み上げ・手続き・案内更新管理を提供経路から外す。平文の自動保存には置き換えない。

標準処理は端末内。フォーム値を拡張へ複製・送信せず、自動変換・上書き・送信代行もしない。AI サーバーの追加は本計画に含めない。原 PDF 自体の暗号化・読み取り専用などの制約は保管庫廃止と分け、維持する。

フォーム支援は、ブラウザーでサイトアクセスを許可済みの HTTP(S) 文書ではフォーカスだけで自動表示し、サイドパネルの起動を要求しない。未許可時はブラウザー標準の許可だけを使う。PDF はファイル選択を必須の入口とし、ドラッグも同じ入口で扱う。表示中 PDF の取得は対象環境で成立を確認できた場合に同じ入口へ加え、非対応時はファイル選択へ案内する。独立した URL 入力画面は作らない。

### 今回の記入プレビュー追加の順序

既存の最短保存を保ち、工程4へ次の順で追加する。追加前の2756・9ffの合格結果を、今回のプレビューの合格として転記しない。

1. `PdfSession.renderPreview` と専用workerを接続する。保存と同じwriterを使い、書き込みmode・action除去確認・ページ判断（`pageReviews`）・原本の制約を維持した一時PDFを作る。原本・正式保存・検査済み出力を変更しない境界を先に確認する。不正な型・長さ・条件・ページ判断の矛盾はエラーとして表示し、原本へのfallbackで隠さない。
2. 回答・修正・ページ判断を含むsnapshot一つの一時PDFを保持し、同じsnapshotでのページ・倍率変更は再利用する。フォントはセッション内で再利用し、資料切替・終了時に一時データとworkerを解放する。
3. `PdfPreview` で入力が約300ms落ち着くのを待ち、IME変換中は保留する。全回答と修正・削除・選択変更を反映し、前後移動でも回答を保持する。
4. private canvasへ描画し、回答・文書・ページ・倍率の世代が一致する最新結果だけを表示する。更新中・失敗と現在の描画を区別し、遅着で上書きしない。修正中・読み取り専用資料では原本を表示する。
5. 日本語、複数項目、削除、選択肢、修正採用／取消、連続入力・IME、遅着・破棄・再利用、原本と保存用出力の保持を意味のある試験で確認する。不整合な回答のエラーと修正後の復帰も確認する。型検査、両ビルドとpackage検証、実拡張で入力から保存・再読込までを確認し、同じsourceHashへ結果を結び付ける。
