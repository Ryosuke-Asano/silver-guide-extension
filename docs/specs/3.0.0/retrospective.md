# Silver Guide 3.0.0 に向けた振り返り

作成日：2026-10-20 JST。既存のコード、設計・検証記録と、このチャットで共有された経験に基づく。過去の検証を今回再実行した結果ではない。

## 1. 最重要の教訓

利用者から、3.0.0 では「機能の簡素化」「ボタンを多くしすぎないこと」「直感的に操作できること」を教訓にしたいと共有された。以前の別ページの実装は、PC 操作に慣れている本人でも間違えるほどボタンが多く、書き直しになったという。

この UI を書き直すことになったという利用者の振り返りを、今回の設計の前提として扱う。当時どのボタンで誤ったかと、書き直しの具体的な差分は未特定。特定の保存バグをこの経験の原因と断定しない。

3.0.0 の中心課題は、各画面で「今何をしているか」「次に何を押すか」「間違えたらどう戻るか」が分かることである。高度な機能をすべて別メニューへ詰めるだけでは、機能選択の負担は解決しない。

## 4. 最新の改善を出発点にする

`31458b51` の PDF 改訂では、通常入力のたびに意味・記入者・必須性の確認チェックを要求する工程を外した。推定値を確認済みへ書き換えることはせず、回答の型・原本制約・配置・文字数・出力検証を維持している。

記録上は 649 テスト、型検査、両ビルドが成功し、Chromium では日本語回答を含む実ダウンロードと再読込を確認した。Floorp は実画面・回答保持の確認で、ダウンロード完了は未確認。macOS 実機・利用者試験・新たな認識精度や正式性能の認定も行っていない。[記録](../../assets/validation-31458b51-pdf-entry.json)

この改善を戻して、確認ボタンや工程を再び通常操作へ増やす設計は避ける。一方、ボタンが少ないことだけを、初見で迷わないことの証明にはしない。

## 5. 失敗と分けて残す未達条件

- d5 固定版の校正済み自動提案は 0 件。precision は未定義、coverage は 0%。位置精度の高さを意味の自動判断の達成へ読み替えない。
- 旧版で測った正式性能を、画面を変更した後の版の性能として扱わない。高性能な開発機の結果は、低い仕様の端末や全利用者の結果を保証しない。
- 対象利用者による操作試験、支援技術、実機・実保存の一部、署名配布や保守体制には未確認・未定の項目がある。

根拠：[品質評価](../../quality-evaluation-20261013.md)、[実装状況](../../implementation-status.md)、[検証の限界](../../verification.md)。

検証側にも、長いテスト用 profile パス、実際には適用されていないブラウザー拡大、自動スクロール直後の命中判定などの問題があった。製品バグ・認識精度の未達・検証道具の不具合を、別々に記録する。

## 6. 原因についての仮説

以下は調査からの解釈であり、利用者試験による因果の証明ではない。

1. 機能の網羅を先に進め、通常の完了経路と主操作の数を十分に絞れていなかった。
2. 通常の入力、詳細な認識修正、出力検証、保存管理を同じ場面で意識させたことで、利用者が内部工程を理解する必要が生じた。
3. 自動試験の数や機能の実装有無で進捗を判断し、利用者が迷わず完了できるかの確認が後になった。
4. 追記の多い文書に旧版と新版の説明が混在し、現在の標準操作を判断しづらくなっていた。

3.0.0 は、まず通常画面の少ない操作で課題を完了できるかを検証し、PDF・フォーム入力・解説を完了するために必要な補助だけを残す。

## 7. 今回決めた簡素化

2026-10-20、利用者から、パスワード保護機能も操作の邪魔になるので削除し、機能を「PDF 関連」「フォーム入力」「解説」に絞る方針が示された。

これを受け、3.0.0 では独自のパスワード保護・保管庫・ロック・解除と、付随する下書き一覧・保存履歴・登録情報・バックアップを対象外とする。別 Reader、読み上げ、手続きチェックリストなども増やさない。フォーム入力は前の初稿の保留扱いから、提供する三機能の一つへ変更する。

基本の入力保持や取消、PDF の書き出しは残す。暗号化を外して平文の下書きを自動保存する実装には置き換えない。既存の保管庫に関する不具合の記録は過去の事実として残すが、その機能を新版へ戻す理由にはしない。

同日の画面検討で、フォーム入力をサイドパネルへ移す初期案に対し、利用者から「元の欄にフォーカスしたときに補助が出るほうがよい」と提案された。元の欄へ直接入力し、その近くに短い案内だけを表示する案へ変更する。別入力欄・独自の前後移動・反映工程を外し、サイドパネルは文章の解説に使う。

その後、短い案内は小さな Tooltip とし、基本位置を入力欄の上側へ変更した。2026-10-20、利用者は一度「フォーム補助＝上側 Tooltip、文章解説＝サイドパネル、PDF＝専用タブ」の構成を採用した。フォーム用サイドパネル、横長の説明枠、右側 Tooltip は非採用の検討履歴である。

同日の試用で、旧版は難しい単語をクリックすると解説が出たことが確認された。利用者の最終指示は「3.0.0も下線の単語をクリックすると以前と同じように解説のポップアップが出る」こと。これを優先し、単語の基本経路を**本文の下線クリック→ページ内ポップアップ**へ戻す。範囲選択によるサイドパネル解説は補助として残し、フォームの上側 Tooltip と PDF 専用タブは維持する。[Spec](spec.md) と [実装作業順](implementation-plan.md) は、この改訂後の採用構成を正とする。これは旧版の保管庫・Reader・管理メニューを戻す変更ではない。
