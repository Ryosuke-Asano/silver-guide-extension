# Silver Guide 3.0.0 Spec

確定日：2026-10-20 JST。状態：**三機能を採用済み。文章解説の基本操作を「下線の単語をクリックしてページ内ポップアップを読む」へ改訂**。実装の確認範囲と公開条件は [実装状況](implementation-status.md) に記録する。本書を3.0.0の仕様の正本とし、旧版の設計や途中の画像案より優先する。

## 1. 目的と採用構成

Silver Guide は、ウェブページや書類の理解と記入を、少ない操作で支援するブラウザー拡張機能である。高齢者を優先しつつ、PC 操作の経験を問わず、入力する場所と次の操作が分かることを目指す。

提供する機能は次の三つに限定する。

| 機能 | 採用する画面 | 基本の操作 | 拡張が追加する通常操作 |
| --- | --- | --- | --- |
| フォーム補助 | 元の入力欄の**上側の Tooltip** | 欄へフォーカス → 短い説明を読む → 元の欄へ直接入力 | 原則ボタンなし。元サイトの Tab 移動・確認・送信を使う |
| 文章の解説 | 単語の近くの**ページ内ポップアップ**。文章の範囲選択はサイドパネルで補助 | 下線の単語をクリック → 元の言葉と短い説明を読む | ポップアップの「閉じる」一つ。基本操作にアイコンやパネルの起動は不要 |
| PDF | **専用タブ**。左に一問、右に記入プレビュー | 開く → 記入と自動プレビュー → PDF を保存 | 戻る／次へ。最後の次へが PDFを保存に変わる。途中保存も選べる |

画面の見た目と画像は [画面仕様](screen-design.md)、実装順と工程ごとの完了条件は [実装計画](implementation-plan.md) に記載する。過去の問題と根拠は [振り返り](retrospective.md) に残す。

## 2. 過去の失敗から守る原則

- 機能を増やす前に、通常の完了経路を成立させる。全機能を巨大なメニューへ移すだけでは簡素化としない。
- 元のページや入力場所を保つ。フォーム用の別入力欄、独自の戻る／次へ、フォームに反映する工程を作らない。
- 誤操作の防止を、確認チェックやダイアログの追加だけで解決しない。PDF の前後移動・修正・失敗時には回答を保持する。
- フォーカスやスクロールで、押しているボタンを動かしたり消したりしない。入力欄・既存エラーを補助表示で隠さない。
- 機能の実装有無やテスト総数と、初見の人が迷わず完了できることを分けて確認する。

白地・青緑の主操作・濃い文字・淡いミントを継承する。PDF の主操作は各状態一つに絞り、戻るは左、進む・保存は右に置く。フォームは追加ボタンを置かず、単語解説は下線クリックと閉じるだけで読める構成にする。

## 3. フォーム補助

### 3.1 操作の流れ

1. ブラウザーでサイトへのアクセスが許可され、支援の対象となった通常の HTTP(S) ページで、入力欄をクリックするか Tab で移動する。
2. 欄のすぐ上へ Tooltip を表示する。フリガナなら「カタカナで入力します。」「例：ヤマダ ハナコ」の二行程度とする。
3. 元の欄へそのまま入力する。補助へフォーカスを移さず、別の欄に入力内容を複製しない。
4. 次の欄へ移ると案内も切り替わる。欄からフォーカスが外れるか Escape を押すと閉じる。Escape で閉じた同じ欄では、次のフォーカスまで再表示しない。
5. 元サイトの確認・送信操作を本人が行う。拡張は値の自動変更・反映・送信を行わない。

### 3.2 Tooltip の表示

- 基本位置は**上側**。画面外になるか前の欄・ラベルを隠す場合だけ**下側**へ切り替える。左右には出さない。
- 欄と画面の幅に収め、レイアウトを押し動かさない。上下とも置けない場合は、元の入力操作を優先して追加案内を出さない。
- 本文は短い説明と必要な例だけ。ロゴ・見出し・ボタン・閉じる X・進捗表示は載せない。
- 元サイトの説明・エラーを優先し、同じ内容を重複表示しない。用途・必須性・形式が不明なら、推測の指示を断定しない。
- 入力欄・ラベル・既存エラー・IME 候補を妨げない。キー入力・コピー＆ペースト・Tab 順を変えず、入力中に時間で自動消去しない。
- 補助は公開ラベル・説明・形式などを使う。パスワード欄や認証など用途の異なる欄へ一般的な記入ヒントを押し付けない。

### 3.3 有効化の条件

フォーム補助はサイドパネルの起動・開閉と独立する。許可済みサイトではフォーカスへ自動追従し、欄ごとの開始操作を要求しない。未許可のサイトではブラウザー標準の権限操作を使い、独自の設定画面や入力開始ウィザードを増やさない。

自動注入・許可の適用範囲・制限されたページ・動的なページ遷移は、最初のブラウザー検証で方式を確定する。現行の「支援開始メッセージで注入する」実装が、そのまま要件を満たすとは扱わない。

## 4. 文章の解説

### 4.1 下線の単語をクリックする（基本）

1. 許可済みの通常ページで、同梱辞書に説明のある本文の単語へ下線を付ける。元の文章の文字は変えない。サイドパネルの起動は不要。
2. 下線の単語をクリックすると、その近くへページ内の非モーダルな解説ポップアップを一つだけ表示する。Tabで単語へ移動し、Enter／Spaceでも開ける。
3. ポップアップは元の言葉・短い説明・「閉じる」一つで構成する。モード切替、開始・次へ、設定などのボタンは増やさない。
4. 「閉じる」、Escape、ポップアップの外をクリックする操作で閉じる。別の下線語を開くと同じ一つの表示を更新する。

元のリンク・ボタン・フォーム欄とラベル・編集領域・コードなどには下線や解説操作を追加しない。フォーム内でも公開の本文は対象にできる。元サイトのクリック・送信・編集を妨げない。後から追加・変更された本文も対象にし、削除やページ切替で古い表示を残さない。画面端でも説明が読み取れるよう、表示位置と幅を画面内へ収める。

### 4.2 文章を範囲選択する（補助）

長い文章を読みたい場合は、拡張アイコンから解説用サイドパネルを直接開く。中間の拡張ポップアップや機能メニューは置かない。単語を選ぶと、元の言葉と説明文を表示する。文章では、条件・期限・することなどの「文章の説明」を先に表示し、単語の意味を必要に応じて開ける。原文は「原文を見る」に折りたたんで保持する。説明が見つからない場合は、原文を表示したままにする。パネル内のロゴ・対象ページ名・重複見出し・常時の辞書出典と選択案内は表示しない。別の文章を選ぶと更新し、毎回の「解説する」は要求しない。パネルを閉じる操作はブラウザー枠のものを使う。単独PDFを開く補助操作は、右上の「⋯」に置く。

文章の途中を選んだ場合は、選択箇所を含む文と、段落内の前後各1文を自動で補う。合わせて最大5,000文字とし、入力値・編集領域・非表示の文章・別の段落を補足に混ぜない。選んだ文字列は変えず、補った原文と元の選択箇所をサイドパネルで確認できる。辞書語を単独で選んだ場合は、短い語句の説明を優先する。文脈を取得できない場合も、内容を推測したり、文末だけを行動として表示したりしない。

標準の解説は、既存のローカル辞書照合と原文に基づく条件・注意などの整理を使う。任意の文章を自由に説明できる AI を新設することは今回の範囲に含めない。

説明できた部分、一部のみ説明できた状態、原文のみの状態を区別する。対応する説明がなければ、その旨を短く示す。不明な意味・資格・制度判断を確定せず、元の数字・否定・条件・例外を変えない。

入力欄・パスワード欄・編集領域の内容は、本文の選択として勝手に取り込まない。結果を元タブ・文書の世代に結び付け、タブ切替や遅い応答で別ページの解説を表示しない。

## 5. PDF

### 5.1 操作の流れ

1. 「PDFを開く」からファイルを選ぶ。ドラッグ＆ドロップも同じ読み取り経路へつなげ、独立した操作ボタンは増やさない。
2. 専用タブで読み取る。処理中は進み具合と「中止」を表示し、編集不可なら早い段階で理由を示す。
3. 読み取り後すぐに記入へ進む。左に現在位置・一つの項目・短い説明・入力欄、右に記入プレビューを表示する。狭い画面は質問→プレビューの順にする。
4. 入力が落ち着いたら、保存前の回答をPDF上に仮想的に書き込んで自動表示する。戻る／次へでも全回答を保持し、変更・削除・選択肢の変更を反映する。プレビューは質問の対象位置へ追従する。
5. 必要な場合だけ「この項目を直す」から項目名や記入位置を修正する。修正を採用／取消して、同じ回答・項目・原本位置へ戻る。
6. 最後の次へを、同じ位置の「PDFを保存」に変える。作成・出力の検査・保存を内部で連続実行する。
   2026-10-28追加：「ここまでの入力を保存」を補助操作として用意する。途中保存にも同じ回答・位置・出力検証を適用する。横浜市立図書館のデモPDFは、原本のSHA-256一致時に限り、人が位置を確認した14項目を用いる。手続の内容の6つのチェック欄を一問にまとめ、左の選択欄とPDF上の枠で付け外しできる。対象と範囲は[デモの補足](../../demo-usability.md)に記録する。
7. 保存結果を表示する。失敗しても回答を保持し、原因を直せる項目への移動か再試行を案内する。PDF の保存を申請の提出・受理と表示しない。

### 5.2 機能と制約

- 既存の文字・フォーム欄・画像 OCR・混在ページの処理、日本語出力を再利用する。読み取りできないページや欄なしを、正常な解析完了と混同しない。
- 標準は最新の直接記入方式を継承する。記入者・必須性・ページ判断の全確認チェックを、通常操作の必須工程へ戻さない。次へだけで推定値を確認済みに書き換えない。
- 原本の制約、回答型、文字数、位置、出力の検査は維持する。未記入で保存する場合は、その状態が分かるようにする。
- プレビュー用のPDFはメモリー内だけで作り、原本ファイル・保存済み状態・正式な出力結果を変更しない。更新ボタンは追加しない。日本語IMEの変換中は更新を待ち、確定後に反映する。遅い描画を新しい回答や別ページへ上書きしない。
- 保存と同じ文字・位置の処理を使い、入力欄の元の値を二重に描かない。プレビュー更新中・失敗を区別し、古い結果を最新として見せない。文字が収まらない場合は回答を保持して案内する。補正中は原本を表示し、採用後に記入プレビューへ戻る。
- 原本を見るためのページ・倍率操作は質問の主操作から分け、詳細な編集工具群や工程の切替ボタンを常設しない。
- PDF の質問をサイドパネルへ重複表示しない。PDF 表示中のブラウザーパネルの扱いは実機で確認する。
- 表示中 PDF の取り込みは、対象ブラウザーで取得を確認できた条件で同じ入口へ統合する。取得できない場合はファイル選択へ案内する。独立した URL 入力画面は作らない。
- 元 PDF の暗号化・署名・読み取り専用などの制約を解除したり、一律に編集可能としたりしない。独自の保管庫パスワードを廃止することとは区別する。

### 5.3 ウェブ上のPDF記入・添付連携（2026-10-28改訂）

- 拡張がHTTP(S)ページのPDFリンク・埋め込み・選択済みPDFを検出し、記入操作を表示する。デモURLやページ側の専用JavaScriptを有効条件にしない。
- 利用者の操作後にPDFを取得し、既存の記入エンジンへ渡す。添付先を一意に決められれば直接記入し、複数候補や既存ファイルの置き換えは利用者が選ぶ。添付先がなければ通常の保存へ進む。
- 最後の「入力を完了」で検証済みPDFを元の欄へ戻す。元のinput／change処理を通し、複数ファイル欄では他の添付を保持する。
- 通常サイトの送信操作は選択制。指定したボタン、フォームと送信先を照合し、標準の入力検証・submitイベントを維持する。確認・認証・受理を一般的な推測で突破・完了扱いにしない。
- サイト固有の複数段階操作と完了判定は拡張内のアダプターへ分ける。図書館デモはその一例とし、ページ側は通常のフォームへ戻す。
- PDFは20MiBまで、取得は20秒でタイムアウトする。既存のサイト権限を使い、追加権限や永続的な送信待ち一覧を作らない。実DOM、文書・ジョブ・クライアントIDを照合し、元フォームの通常入力値を拡張へ取り込まない。
- ページ・欄・選択ファイル・送信先が変わった場合は回答を保持して止める。添付、入力不足、フォーム操作済み、アダプターが確認した完了を区別する。

実装の責務、対応範囲、取得・提出の境界は[PDF連携の設計](../../decisions/pdf-web-workflow.md)に定める。

## 6. 削除する機能

次の機能は 3.0.0 へ持ち込まない。画面から隠すだけでなく、起動・状態・処理の依存から外す。

- 独自のパスワード設定・確認・変更、保管庫、ロック・解除・自動ロック。
- 永続下書き、作業一覧、再開・複製、保存履歴、バックアップの書き出し・取り込み。
- 登録情報・プロフィールの保存と再利用。
- 別 Reader、読み上げ、手続きチェックリスト。
- 案内更新・署名鍵・詳細テンプレートを利用者が管理する画面。
- フォームの別入力画面、プレビュー・反映・取消の独自工程、旧ドックの前後移動ボタン。

解説の辞書や PDF 処理に必要な内部データは維持するが、その管理を利用開始の前提にしない。旧機能へのメニューや実行経路を残して、通常の作業から迷い込める構成にしない。

## 7. 入力・状態・データ

| 対象 | 保持する場所と寿命 |
| --- | --- |
| 元フォームの値 | 元サイトの入力欄。拡張は別の回答コピー・反映待ち下書き・保存用の値取得を作らない |
| Tooltip | フォーカスしている欄に紐付く一時表示。欄の削除・非表示・無効化・ページ切替で終了 |
| 下線・単語ポップアップ・選択文と解説 | 対象ページに紐付く一時状態。サイドパネルの結果は対象タブと文書の世代も照合し、別タブ・別ウィンドウへ混ぜない |
| PDF 原本・回答・修正 | 開いている作業タブのメモリー。戻る・修正・中止・出力失敗で消さない |

書類・本文・入力値・回答をストレージ、履歴、診断ログ、バックアップへ自動保存しない。暗号化を外した平文保存を代替にしない。本人が明示的に書き出す PDF は成果物として保存する。

ページや PDF 作業タブの再読み込み・終了、ブラウザー終了後の復元は保証しない。PDF の未出力回答を失う操作には、必要最小限の離脱確認を設ける。元サイトの入力や送信の寿命・確認は元サイトに従い、拡張独自の確認を重ねない。

解析・出力の世代と回答の版を管理し、取消後や変更前の結果を最新として採用しない。通常とプライベートのデータを混ぜない。標準処理は端末内で行い、書類や文章を外部 AI へ送る機能は追加しない。URL 取得や出典を開く場合の通信は、その操作に限る。

旧版の保存済みデータは無断で削除・平文変換しない。必要な取り出しは旧版から更新する際の移行として扱い、3.0.0 の通常 UI に保管庫や復号機能を戻さない。

## 8. 構成と実装方針

- Content：元欄の公開ラベル・説明・形式の取得、フォーカスと Tooltip、同梱辞書語の下線・ページ内ポップアップ、本文選択の取得。フォーム値の別入力・反映は担当しない。
- サイドパネル：選択された文章とローカル解説の表示。ブラウザーごとの API 差は内部で吸収する。
- Background：ユーザー操作、権限、対象タブ・文書の照合、要求の仲介。PDF 原本・回答・復号鍵を保持する前提にしない。
- PDF 専用タブ：一時作業と質問表示。既存の解析・OCR・作成・検査の処理を再利用し、不要な保管庫依存を外す。

既存コードは再利用する境界を先に調べる。旧版の巨大画面へ機能を足し続けることと、全処理を一から作り直すことのどちらも前提にしない。基準となる未コミット作業を保全してから、三経路を独立して成立させ、不要な旧経路を除去する。

作業順は **保全 → 起動・権限と三画面の最小確認 → Tooltip → 解説 → PDF の最短保存 → PDF 修正・追加対応 → 旧機能の除去完了 → 実機と初見操作・配布物の検証** とする。詳細な対象ファイルと工程の出口は [実装計画](implementation-plan.md) を使う。

| READ-02 | 下線から単語の説明を読む | 許可済み本文の辞書語に下線が付き、クリック・Enter・Spaceで一つのページ内ポップアップが開く。元語・短い説明・閉じるだけを表示し、Escape・外側クリックでも閉じる。パネル起動は不要 |
| READ-03 | 元ページと動的本文の保持 | 元のリンク・ボタン・フォーム欄とラベル・編集領域・コードを除外し、その動作を変えない。フォーム内の公開本文や動的に加わった本文にも対応し、消えた単語の表示を残さない |
| PANEL-01 | パネルと元ページ | アイコンから直接開き、選択で更新できる。開閉で元フォームの値が変わらず、別タブ・別ウィンドウの結果を混ぜない |
| PDF-01 | 日本語の実保存 | 記入・前後移動・保存を行い、保存した実ファイルを開き直して、日本語・選択値・配置・元ページを確認できる |
| PDF-02 | 修正・不対応・未記入 | 対応不可は早期に示す。必要な欄だけ修正でき、戻っても回答を失わない。不明を確認済みにせず、未記入の状態も分かる |
| PDF-03 | 入力ごとの記入プレビュー | 入力・修正・削除・選択値を自動でPDFへ仮想書き込みし、前後移動でも全回答を保持する。IME確定前・遅着・失敗を区別し、原本と正式な保存結果を変更しない |
| DATA-01 | 中止・変更・失敗 | 旧処理の結果を採用せず、PDF の回答を保持して再試行できる |
| DATA-02 | 自動保存の廃止 | 書類・本文・回答の永続保存と診断ログへの混入がない。フォームの別回答コピーを作らない |
| SIMPLE-01 | 旧機能を要求しない | 初回から三機能の完了まで、パスワード・保管庫・下書き管理の表示・待機・起動依存がない。旧画面へ迷い込む入口もない |
| UX-01 | 初見で完了 | 操作説明なしで、フォーム入力・文章解説・PDF 保存の代表課題を完了できる |
| UX-02 | 少ない操作 | フォームは追加ボタンなし、単語解説は下線クリックと閉じる一つ、範囲選択の解説は毎回の開始なし、PDF は通常の戻る／次へ／最後の保存だけで進める |
| UX-03 | 誤操作からの復帰 | PDF の前項目や修正画面から同じ回答・項目へ戻れ、最初から再入力を求められない |
| UX-04 | 操作の区別 | 元フォームの送信と PDF の保存を混同せず、入力する場所が一つに見える |
| UX-05 | 元ページの保持 | 補助・パネルの開閉・文章選択をしても、本文・元欄の値・元サイトの操作を壊さない |
| UX-06 | 本当のクリック | フォーカス・スクロール・描画更新の途中でも、意図した一回の pointer・キー操作が成立する |
| A11Y-01 | 拡大・キー・日本語入力 | 対象環境で拡大、Tab・Shift+Tab・Escape、日本語 IME、狭い幅を確認し、主操作と現在位置を見失わない |

初見評価の前に、代表ページ・PDF・課題・対象者・介助と誤操作の記録方法・合格水準を固定する。まず本人による操作確認を行い、その結果を対象利用者全体の分かりやすさの証明には代用しない。

PDF の位置・文字・ラベルや種類・記入対象の意味は別々に評価する。位置が合うだけで認識成功とせず、既存の精度未達を新版の合格へ読み替えない。試験結果は同じソース・配布物・ブラウザー・OS と結び付ける。

## 10. 実装で確定する事項

三機能と画面配置の選択は確定している。次はその実現方法と検証範囲を決める。

| 項目 | 確定する時点 |
| --- | --- |
| サイト権限とフォーム補助の自動起動、サイドパネル API、制限ページの扱い | 最初のブラウザー検証。三機能の本実装へ進む前 |
| 対応するフォーム部品・PDF 条件、表示中 PDF の取得可否、認識・出力の評価資料 | 各機能の基本動作を作る前に試験条件を固定し、追加対応ごとに更新 |
| 正式対応の OS・ブラウザー、初見評価、旧版からの移行、署名配布・問い合わせ | 配布準備。未実施の環境を対応済みと表示しない |

現在の構成合意は実装完了や公開品質の認定を示さない。旧版の性能・精度・テスト件数は [過去の記録](retrospective.md) として扱い、3.0.0 の実測は実装後に取得する。
