# Silver Guide UI 設計

## 1. 固定するデザインシステム

Silver Guide の見た目は、既存 `yasashiku-yomu-extension` の設計を**完全に再利用する**。新しい配色、グラデーション、別の角丸、別系統のアイコン、異なる文字サイズ規約を追加しない。

基準資料は次の二つである。

- `../../yasashiku-yomu-extension/docs/design-system.md`
- `../../yasashiku-yomu-extension/src/popup/popup.css`

Silver Guide で新たに必要になる支援ドックとツールチップは、機能だけを追加し、以下の色・文字・余白・操作面をそのまま適用する。

- 白い背景に濃い文字を置き、情報量を詰め込みすぎない。
- 最初の行動は一つに絞り、大きな文字ラベルで示す。
- 用語・説明・次の行動を視覚的に分け、現在地を迷わせない。
- 操作の意味を色やアイコンだけに委ねない。

## 2. トークン

| 役割 | 値 | 用途 |
| --- | --- | --- |
| 背景 | `#ffffff` | ポップアップ、支援ドック、ツールチップ |
| 主文字 | `#0f2747` | 見出し、本文、境界線 |
| 主操作 | `#076c78` | 「支援をはじめる」「次の項目へ」 |
| 主操作ホバー | `#055b65` | ポインタ操作時 |
| フォーカス | `#0c75a6` | 3px のキーボードフォーカス輪郭 |
| 罫線 | `#cad3df` | セクション区切り、入力の周囲 |
| 原文・参照枠 | `#b5d5ec` | 原文、公式案内への補助枠 |
| やさしい説明枠 | `#a8cfab` / `#f3fbf0` | 用語の言い換え、入力のヒント |
| 成功 | `#176535` | 完了を示す補助表示 |
| 注意 | `#a02222` | 問題を示す補助表示 |

背景は純白のままとし、グラデーションや装飾目的のカード群は使わない。主操作色は既存どおりの `#076c78` を固定し、前回提示した濃い青の配色へ変更しない。

## 3. 文字・余白・操作面

| 要素 | 規約 |
| --- | --- |
| 本文 | 18px 以上、行間 1.6 以上 |
| ポップアップ見出し | 28px、行間 1.3 |
| 主操作 | 21px・太字・最小高 58px |
| 副操作 | 18〜21px・最小高 52px |
| アイコン | 原則として文字ラベルと併記 |
| 余白 | 8px 単位。まとまりの間は 16〜24px |
| 角丸 | 操作 8px、枠 10px、支援面 12px |
| フォーカス | `outline: 3px solid #0c75a6; outline-offset: 3px` |

## 4. コンポーネント

### 4.1 ポップアップ — 既存部品をそのまま使う

- 既存と同じ 390px 以上の幅、22px の内側余白、28px の見出し、21px・58px 高の主ボタンを使う。
- 見出しだけを「Silver Guide」に置き換える。
- 最初の大きな主操作は既存と同じ見た目で「このページを支援する」または開始後の「支援を停止する」とする。
- 既存のラジオグループ、スイッチ、設定リンクを流用し、設定は「文字の大きさ」と「元の文章を表示」の二つに限定する。
- フッター近くに既存のアウトラインアイコンの規約で鍵アイコンと **「入力内容は送信しません」** を表示する。

### 4.2 支援ドック — 既存パネルを拡張する

- デスクトップでは画面右端に固定せず、既存のページ内パネルと同じ白背景、12px 角丸、`#cad3df` の罫線、控えめな影を使う。幅は 320〜380px とし、利用者が閉じる・縮める・位置を戻す操作を持つ。
- 上部に現在の支援種別（「入力のヒント」または「手続きへの案内」）と閉じるボタンを置く。
- 本文は「この欄には何を書く？」「準備するもの」「次の項目へ」の順で読むだけで理解できる構造にする。
- 進捗を表示する場合は、フォームの入力済み状態から推測しない。ガイドパックで定義した手順位置だけを「3 / 8」のように示す。

### 4.3 用語ツールチップ — 既存の説明枠を使う

- 用語は既存の `#0c75a6` の 3px フォーカス輪郭とリンク風の下線で示し、本文の可読性を壊さない。
- 本体は白背景・10px 角丸・`#cad3df` の罫線、やさしい説明部分は `#f3fbf0` の背景と `#a8cfab` の枠を使う。
- ツールチップは用語の近くに表示し、狭い画面・端部では画面内へ収める。
- 順序は「用語 → やさしい説明 → 必要なら公式導線 → 閉じる」。
- `Escape`、閉じるボタン、用語からフォーカスを外す操作で閉じる。ツールチップ内にフォーカスを閉じ込めない。

## 5. 状態の言葉

| 機能 | 利用者に見せる言葉 |
| --- | --- |
| 全ページ共通 | 読む、言葉の説明 |
| 行政申請 | 入力する、入力のヒント、この欄には何を書く？ |
| 行政案内 | 進む、手続きへの案内、公式ページを開く |
| 安全 | 入力内容は送信しません、支援を停止する |

専門用語の説明そのものも、結論を最初の一文に置き、必要なら「詳しく見る」で補足する。

## 6. レスポンシブと衝突回避

- Floorp のデスクトップ利用を最優先にする。表示域が狭いとき、支援ドックは本文上の下部シートへ切り替える。
- ページ本文のクリックやスクロールを妨げない。ドックの外側を無断で覆うモーダルにしない。
- 支援 UI の CSS は Shadow DOM に閉じ込める。サイト固有のスタイルが文字サイズ・色・レイアウトに干渉しないようにする。
